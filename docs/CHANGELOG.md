  - **动机**：`full_page` 只把画幅拉到内容高度，**宽度仍是 `width`**。页面内容窄于视口时右侧留白等于差值 —— 固定宽度的卡片模板（HTML→图 的主力场景）必然踩到。实测某模板卡片 `width:1440px` + `zoom:0.5` = 720 CSS px，默认 1280 视口下右侧 **43.8% 是白的**。这不是缺陷，Puppeteer / Playwright 的 `fullPage` 同样只取 `documentElement.scrollWidth`；别的 HTML→图 管线出图贴边靠的是 `elementHandle.screenshot()`，本内核此前没有对应能力。
  - **接线**：`RenderOptions.selector` → `shot_render_options.selector`（**追加在结构体末尾**，尺寸变化即 ABI 变化，libshot 与调用方须同版本）→ `--selector CSS` / JSONL `selector` → `ScreenshotSettings.selector`。`selector` 优先于 `full_page`；`width` 仍参与布局，响应式模板照常按该视口宽度断点，只是最终画幅换成命中元素。选择器路径同样先把 view 撑到 `contentsSize().height()`，否则高于视口的元素下半截取不到（有回归覆盖：300×2000 卡片放进 400 高视口）。
  - **几何选型的坑（实测推翻第一版）**：初版直接复用 WebCore `snapshotNode()` 用的 `subtreePaintRootRect(RespectTransforms::Yes)` —— 看似最正统的官方节点截图几何，**结果错得离谱**：真实模板上出图 1080×1799 CSS px，**比整个文档（1199 高）还大**。读实现才明白它是以 `absoluteBoundingBoxRect` 起步、再把**每个后代 layer 的绝对矩形并进来**（`RenderObject.cpp:881` 的 `addAbsoluteRectForLayer` 递归），得到的是含 ink overflow 的绘制包围盒 —— 那是「独立绘制该节点时不能裁掉阴影」才需要的语义，模板里的 `absolute inset-0` 氛围层与大范围 `box-shadow` 会把它撑爆。改用 `absoluteBoundingBoxRect(useTransform=true)`（元素自身边框盒，等同 `getBoundingClientRect` + 滚动偏移，即 Puppeteer 的取景）后正确。**教训：`snapshotNode` 的几何是为「把节点画成一张独立图」设计的，不等于「在页面里裁出这个元素」。**
  - **验证**：`selector` 出图与手算 `width:720` + `full_page` 的产物 **SHA-256 逐字节相同**（1440×2398），但不必再从模板反推宽度。`shotcli --selector '#card'` 对 `width:1440px;zoom:0.5;height:800px` 的卡片给出 720×400，zoom 折算正确。失败路径给具体原因而非笼统 "render failed"：新增 `SHOT_ERR_SELECTOR_NOT_FOUND`（状态码 8），覆盖选择器非法 / 没命中 / 命中元素 `display:none` 三种，失败后常驻进程存活。Node SDK 测试 9/9 通过，其中 5 个为本次新增 —— 含一条专门锁边框盒语义的回归（卡片内塞 `left:900px` 绝对定位块 + `box-shadow 0 0 0 400px`，断言画幅仍是 300×200），**初版的 4 个测试发现不了那个几何 bug，因为合成用例没有溢出的后代**。

**M1 打通过程中踩到并已解决的关键坑（未来会话必读）**：
1. **主题符号缺失**：`RenderTheme/Theme/ScrollbarTheme::singleton` 的定义整体包在 `#if USE(THEME_ADWAITA)` 内。Win 端口用 Adwaita 主题，故 `OptionsShot.cmake` 必须 `SET_AND_EXPOSE_TO_BUILD(USE_THEME_ADWAITA ON)`，否则链接期缺三个 singleton。
2. **dwrite 系统库**：`FontCacheSkiaWin` 用 `DWriteCreateFactory`。WebCore 是 OBJECT 库，其 PRIVATE 系统库依赖**不传递**给消费者，须在 `shot/CMakeLists.txt` 的 `shotcli_LIBRARIES` 显式加 `dwrite`。
3. **RunLoop 双初始化崩溃**：`WTF::initializeMainThread()` 内部已调 `RunLoop::initializeMain()`；`ShotGlobal::initialize` 不可再调，否则 `RELEASE_ASSERT(!s_mainRunLoop)` 崩。
4. **LoaderStrategy 不能为 nullptr**：`Page::firstTimeInitialization()` 会解引用 `platformStrategies()->loaderStrategy()`（调 `addOnlineStateChangeListener`）。已在 `ShotPlatformStrategies.cpp` 提供最小 `ShotLoaderStrategy` 桩（29 个纯虚全实现；带 `CompletionHandler` 的方法必须回调否则析构断言）。M2 用 curl 直驱替换。
5. **进程退出 teardown 崩溃**：正常退出时 `ThreadGlobalData::~ThreadGlobalData`→`FontCache`→`Font::~Font` 再度访问 `threadGlobalData()`→重建→`MainThreadSharedTimer` 断言崩。WebCore 线程级单例被设计为**进程退出时泄漏**，不支持干净静态析构。`cli/main.cpp` 在写完 PNG（已 flush 落盘）后 `std::_Exit(0)` 硬退出，跳过一切静态析构/atexit。**M2 起 C ABI/libshot 场景（同进程多次 render、不能硬退出）需另找干净收尾方案**（如每次 render 后不销毁线程全局、复用 Page，或显式 leak）。
